## Dev Technical Guidance

### Previous Story Context

Story 1.1 established the foundational Astro.js + Tailwind CSS project structure. The development environment is ready, and the basic project structure includes the required `src/content/blog/` directory for markdown articles.

### Content Collections Implementation

Astro Content Collections provide type-safe content management with automatic validation. This is the core system for processing markdown files.

**Required Content Collection Schema:**

```typescript
// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blogCollection = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    date: z.coerce.date(),
    tags: z.array(z.string()).default([]),
  }),
});

export const collections = {
  blog: blogCollection,
};
```

[Source: docs/architecture.md#api-reference]

### Article Data Model

The system follows this specific data structure:

```typescript
export interface Article {
  id: string;
  slug: string; // Generated from filename
  body: string;
  data: {
    title: string;
    date: Date;
    tags: string[];
  };
}
```

[Source: docs/architecture.md#data-models]

### Content Processing Requirements

**Frontmatter Format:** Articles must support this exact frontmatter structure:

```yaml
---
title: Article Title Here
date: 2022-12-27
tags:
  - Web
  - Development
---
```

**URL Generation:** URLs should be automatically generated from filename without extension. For example: `my-article.md` → `/blog/my-article`

[Source: docs/architecture.md#content-processing-apis]

### File Locations

**Content Location:** All markdown articles must be placed in `src/content/blog/`

**Dynamic Route:** Create `src/pages/blog/[...slug].astro` for individual article pages

**Utilities:** Create `src/utils/blog.ts` for content processing functions

[Source: docs/architecture.md#project-structure]

### Syntax Highlighting Configuration

Use Astro's built-in Shiki syntax highlighter which provides:
- Language detection and highlighting
- Theme support (important for retro aesthetic)
- High performance with no client-side JavaScript

The highlighting must integrate with the retro terminal aesthetic planned for later stories.

[Source: docs/architecture.md#modern-web-features-integration]

### TypeScript Integration

All content processing must be fully typed:
- Enable strict mode for content collections
- Use TypeScript interfaces for all data structures
- Ensure build-time validation of frontmatter

[Source: docs/architecture.md#coding-standards]

### Testing Requirements

Since this establishes the core content pipeline, verification must include:
- Frontmatter parsing accuracy
- URL generation correctness
- HTML semantic structure validation
- Syntax highlighting functionality

### Semantic HTML Requirements

Generated HTML must follow proper semantic structure:
- Article content wrapped in `<article>` elements
- Proper heading hierarchy (H1 for title, H2+ for content sections)
- Time elements for dates with proper datetime attributes
- Code blocks with appropriate language attributes
