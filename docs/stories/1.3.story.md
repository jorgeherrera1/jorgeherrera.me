# Story 1.3: Article List Homepage

## Status: Draft

## Story

- As a reader
- I want to see a list of all available articles on the homepage
- so that I can browse and select content to read

## Acceptance Criteria (ACs)

- 1: Homepage displays all articles in chronological order (newest first)
- 2: Each article entry shows title, publication date, and brief excerpt
- 3: Article titles are clickable links to individual article pages
- 4: Articles without dates default to file creation date
- 5: Empty state message displays when no articles exist
- 6: Page is responsive and works on mobile devices

  - [ ] Implement article sorting by date (newest first)

  - [ ] Make article titles clickable links to individual pages

  - [ ] Modify `src/pages/index.astro` to fetch and display articles

## Dev Technical Guidance

### Previous Story Insights

Story 1.2 established the core content processing pipeline with Astro Content Collections and created essential utility functions in `src/utils/blog.ts`. The article data model and content schema are now in place with proper TypeScript typing. The `getAllArticles()` function and content processing utilities are available for homepage implementation.

### Component Specifications

**ArticleList Component** should follow the established pattern from project structure [Source: architecture/project-structure.md#component-architecture]:

- Location: `src/components/content/ArticleList.astro`
- Purpose: Display multiple articles in a list format for homepage
- Props: `articles: Article[]` (typed interface from content collections)
- Structure: Semantic HTML with `<article>` elements for each item

**ArticleListItem Component** (optional refinement):

- Location: `src/components/content/ArticleListItem.astro` 
- Purpose: Individual article entry display within the list
- Props: `article: Article` with title, date, tags, and generated excerpt

### Data Models

Article interface is already established from Story 1.2 [Source: architecture/project-structure.md#data-models]:

```typescript
export interface Article {
  id: string;
  slug: string; // Generated from filename
  body: string;
  data: {
    title: string;
    date: Date;
    tags: string[];
  };
}
```

### API Specifications

Content Collections API is configured and ready to use [Source: architecture/project-structure.md#api-reference]:

// Available from Story 1.2 implementation

### Technical Constraints

**Astro Static Generation:** All content processing must happen at build time using Astro's static generation capabilities [Source: architecture/tech-stack.md#framework]

**TypeScript Strict Mode:** All components and utilities must be fully typed with strict TypeScript [Source: architecture/coding-standards.md#typescript-configuration]

**Responsive Design:** Must work across all device sizes with Tailwind CSS responsive utilities [Source: architecture/tech-stack.md#styling]

### Styling Requirements

**Tailwind CSS Integration:** Use Tailwind utility classes for all styling, following the utility-first approach [Source: architecture/coding-standards.md#css-standards]

**Monospace Typography:** Maintain consistent monospace font (JetBrains Mono) across all text elements [Source: architecture/tech-stack.md#fonts]

**Semantic HTML:** Use proper semantic elements (`<article>`, `<time>`, `<h1>`, etc.) for accessibility and SEO [Source: architecture/coding-standards.md#astro-component-standards]

### Content Processing Requirements

**Date Handling:** Articles without dates should fallback to file creation date or build date [Source: architecture/coding-standards.md#content-standards]

**URL Generation:** Article links should use the established slug-based routing from Story 1.2 (`/blog/[slug]`) [Source: architecture/project-structure.md#content-processing-apis]

**Error Handling:** Follow established error handling strategy with build-time validation [Source: architecture/coding-standards.md#error-handling-strategy]
